# Concurrency architecture

Process isolation permits concurrent compression and extraction without sharing the non-concurrent SevenZip singleton. `OutputPathIdentity` resolves the nearest existing directory through its Windows handle into a volume path and preserves missing suffixes. File leaves retain their parent/name identity through replacement. Source scans resolve their selected roots once and reuse those mappings rather than opening a handle for every file. Legal links in selected output roots and their ancestors therefore share the same output identity. An automatically generated compression leaf that already names a directory reparse point is rejected before writing: replacing that link would change its identity. Ordinary directory collisions and file hardlinks/symlinks retain their existing replacement semantics. SMB falls back to a handle-derived DOS/UNC path when a volume GUID is unavailable; network server aliases and external link replacement are not covered by this guarantee.

Each output holds stable, path-hashed ancestor lock files with shared read access and an exclusive leaf. The canonical and legacy path chains are merged and acquired in one ordinal order, with an exclusive leaf taking precedence over a shared request for the same key. Siblings remain concurrent while identical and nested outputs wait. Stable zero-length lock files live under the current user's fixed LocalAppData/Temp/Lhamiel-extraction-locks and are retained to avoid splitting a lock identity through deletion/recreation; OS handle release recovers crashed workers. Output mutexes likewise acquire canonical and legacy keys in a consistent order. This preserves cooperation with prior lexical gates using the same spelling; it cannot add cross-process protection to older extraction code that never acquired it or repair alias handling inside an old worker.

Fixed settings, password prompts, registry metadata and tracked-temp operations use `CrossProcessResourceGate.EnterMetadata` / `EnterMetadataAsync` to retain the previous lexical mutex identity. Active workers hold exclusive external temporary-directory leases under fixed LocalAppData/Temp/Lhamiel_TempLeases; cleanup probes those leases before deleting aged entries, independently of TEMP/TMP environment changes. Lease sidecars never enter archive payloads and are deleted on handle closure.
