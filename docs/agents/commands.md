# リリース再開コマンドの契約

コマンドは [ci-cd.md](ci-cd.md#cicd) を参照する。

## 作業フォルダーと再開

Release preparation and distribution use a validated work directory under the user's Temp, outside the repository and Codex directories, with no reparse-point ancestors or contents. A fresh run requires an empty directory and generates and prints a unique path if none is supplied. Resuming requires the existing absolute path through `WorkDirectory`; the script does not automatically delete existing work. RID-specific `publish-<RID>/`, `build-<RID>/`, and `shell-<RID>/` trees and the shared Velopack output `packages/` reside there. Tool temporary outputs use its `temp/` subtree, with the original TEMP/TMP restored on exit. Preparation and distribution can be resumed separately in that same directory. `ReusePublish` checks the existing executable's product version against `Directory.Build.props` and validates the shell DLL/MSIX signatures and Certum subject before reusing a RID's publish directory; a missing executable triggers that RID's build. Required application/backend files and license notices are checked even on reuse, and Velopack signs the application during repackaging. A new build initializes the RID's Visual Studio Developer Shell and passes its tools to AOT; shell generation can use the existing MSVC compiler directly when the platform toolset definition is missing, retaining the project's Release flags.

`UploadOnly` skips building and packaging, using completed files in `<WorkDirectory>/packages/`. Before upload, each selected channel's manifest must contain assets of the current version with filename-only paths; package sizes and SHA256 hashes must match, the channel's Setup must exist, and artifact executables must have valid signatures from the configured Certum subject. This avoids rebuilding already signed packages after a distribution failure. These options still run the normal tooling/signing preflight and, when uploading, the upload/purge acceptance and retention flow described in [the release flow](../design/release-process.md#update-and-release). They do not relax release validation or establish source freshness for reused publish output.
